# Database migrations (Alembic)

Migrations are the version control for the database schema. Every change to a
model in `app/models/` must be accompanied by a migration so that every
environment (local, CI, staging, prod) can be brought to the same schema
deterministically.

## Common commands

Run from `backend/` (the app package must be importable):

```bash
# Autogenerate a migration by diffing models against the current DB
uv run alembic revision --autogenerate -m "add documents table"

# Apply all pending migrations
uv run alembic upgrade head

# Roll back the most recent migration
uv run alembic downgrade -1

# Show current DB revision / full history
uv run alembic current
uv run alembic history
```

## Notes

- The DB URL is read from application settings (`app.core.config`), not from
  `alembic.ini` — a single source of truth.
- **Always review autogenerated migrations before committing.** Autogenerate is
  a helpful draft, not an oracle: it can miss server defaults, enum changes, and
  data migrations.
- Generated files are auto-formatted with ruff via a post-write hook.
